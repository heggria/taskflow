## Contract

The ten existing public packages stabilize the mature Taskflow DAG contract:
JSON and TypeScript DSL, twelve phase kinds, validation/planning, live host
execution, budget/retry contracts, interactive Pi approval, fail-closed
headless approval, context isolation, background runs, cancellation, resume,
trace/replay/recompute and admitted declared-filesystem resource transactions.
Host-specific capabilities remain explicit. Pi SDK 1.0 and retained 0.80.3
compatibility must be verified; a source build does not prove installed use.

The complete approved Control Plane, including the S6/S7 adapter/CLI and usable
WebUI, is required for 1.0 acceptance. Its current packaging is not a scope waiver.
`taskflow-control` remains a private source workspace, while its compiled CLI,
MCP adapter and local console are bundled inside the existing public
`taskflow-mcp-core` package. No eleventh public package is introduced. Authenticated
admission, global coordination, durable replay, parked approval/CAS/Receipt,
registry routing and WebUI are implemented; final acceptance is tracked in the
current closure ledger rather than inferred from this plan's old baseline.
Windows named pipes remain non-GA under P13. CharterArc
continues its separate experimental package/version/workflow. The optional
kernel's advanced-feature fallback, resolve-only path limitations, missing
secret/service backends and unbenchmarked journal capacity remain documented.

## Release invariants

- Root, ten public package versions, three plugin manifests and five host MCP
  template pins equal `1.0.0`; package membership comes from the shared release
  contract. Experiments cannot become stable dependencies.
- Local internal dependencies use `workspace:*`; deterministic packed manifests
  pin the exact release version. Fresh npm consumers resolve only the local
  tarballs for Taskflow packages and exercise all exports/declarations/bins.
- The candidate changelog stays `Unreleased`; date it only for an authorized release after the gates pass. Publication requires
  an annotated tag on a verified main commit, npm
  provenance, owner/repository/workflow/commit/integrity verification, all ten
  latest dist-tags, then a stable GitHub Release. Partial publication is failure.
- Exact release-commit CI evidence replaces historical beta evidence. Preserve
  Node 22/24, three-OS process checks, Pi peer matrix, packed consumer, MCP E2E,
  website, CodeQL and retained Cisco/high-severity scanner gates.
